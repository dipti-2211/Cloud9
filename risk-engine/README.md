# risk-engine

A standalone Python micro-service that serves landslide risk predictions from a pre-trained `RandomForestClassifier`. It loads all geospatial rasters and the model **once** at startup and returns predictions in < 50 ms per request.

## Architecture

```
risk-engine/
├── main.py                 # FastAPI app (production runtime)
├── requirements.txt        # Runtime deps (rasterio, xarray, fastapi, …)
├── requirements-dev.txt    # Offline-only deps (pyrosm, geopandas, scipy)
├── scripts/
│   └── precompute_layers.py  # One-time script — run before starting the API
└── data/                   # Large binary assets (git-ignored)
    ├── DEM.tif
    ├── slope.tif           ← generated by precompute_layers.py
    ├── aspect.tif          ← generated by precompute_layers.py
    ├── dist_to_road.tif    ← generated by precompute_layers.py
    ├── landslide_model.pkl
    ├── RF25_indselect_rfp25.nc
    └── north-eastern-zone-260904.osm.pbf   ← used by precompute only
```

## ⚠️ Demo Notes

### Geolocation & HTTPS
`navigator.geolocation` only works on `localhost` or a real **HTTPS** origin. If demoing across
devices on the same WiFi (`http://192.168.x.x:5173`), location will silently fail as "denied".
Use a free HTTPS tunnel for cross-device demos:
```bash
ngrok http 5173
```

### OSRM Public Demo Server
Route planning uses `router.project-osrm.org` — a free public demo server. It is rate-limited
and **not intended for production traffic**. For a production/judging setup that needs guaranteed
availability, self-host OSRM via Docker (still free):
```bash
docker run -t -v $(pwd)/data:/data osrm/osrm-backend osrm-routed --algorithm mld /data/your-region.osrm
```

## First-time setup

### 1. Create a virtual environment

```bash
cd SIH26002/risk-engine
python3 -m venv .venv
source .venv/bin/activate
```

### 2. Copy data files from the `datasets/` directory

The large data files live in `Cloud9/datasets/` (already tracked in the repo):

```bash
# From Cloud9/risk-engine/
cp ../datasets/DEM.tif data/
cp ../datasets/landslide_model.pkl data/
```

> **Note**: `RF25_indselect_rfp25.nc` (rainfall NetCDF) and `north-eastern-zone-260904.osm.pbf` (OSM road network) are excluded from git (>100 MB). Ask a teammate for these files or download from the original sources. The API will still work without the rainfall file (it will use a fallback mean value).

### 3. Install precompute dependencies and run the script

> ⚠️ The `.pbf` file is ~110 MB. The precompute step takes a few minutes.

```bash
pip install -r requirements.txt
pip install -r requirements-dev.txt
python scripts/precompute_layers.py
```

This writes `slope.tif`, `aspect.tif`, and `dist_to_road.tif` into `data/`.
You only need to run this once — the output files can be re-used across sessions.

### 4. Start the API

```bash
uvicorn main:app --reload --port 8000
```

The service will be available at **http://localhost:8000**.

## API Reference

### `GET /health`
```json
{ "status": "ok" }
```

### `GET /predict?lat={lat}&lon={lon}`

| Parameter | Type  | Description                            |
|-----------|-------|----------------------------------------|
| `lat`     | float | Latitude in decimal degrees (WGS-84)   |
| `lon`     | float | Longitude in decimal degrees (WGS-84)  |

Valid coordinate range: DEM coverage area — roughly Dima Hasao district, Assam
(lat 24.97–25.83, lon 92.52–93.47).

**Example:**
```bash
curl "http://localhost:8000/predict?lat=25.5&lon=93.0"
```

**Response:**
```json
{
  "latitude": 25.5,
  "longitude": 93.0,
  "elevation": 742.3,
  "slope": 18.4,
  "aspect": 210.7,
  "dist_to_road": 1234.5,
  "rainfall": 8.3,
  "prediction": 1,
  "risk_percentage": 67.3,
  "risk_category": "High"
}
```

| Field            | Description                                          |
|------------------|------------------------------------------------------|
| `elevation`      | metres above sea level                               |
| `slope`          | terrain slope in degrees                             |
| `aspect`         | terrain aspect in degrees (0 = North, clockwise)     |
| `dist_to_road`   | distance to nearest driving road in metres           |
| `rainfall`       | mean daily rainfall (mm) from IMD gridded dataset    |
| `prediction`     | 0 = no landslide, 1 = landslide predicted            |
| `risk_percentage`| 0–100 model confidence score                         |
| `risk_category`  | Very Low / Low / Moderate / High / Very High         |

---

## Risk category thresholds

| Score       | Category  |
|-------------|-----------|
| < 20 %      | Very Low  |
| 20 – 40 %   | Low       |
| 40 – 60 %   | Moderate  |
| 60 – 80 %   | High      |
| ≥ 80 %      | Very High |

## Running everything together

```bash
# Terminal 1 — Risk Engine (Python)
cd Cloud9/risk-engine && uvicorn main:app --reload --port 8000

# Terminal 2 — Express Backend (Node.js)
cd Cloud9/backend && npm run dev

# Terminal 3 — Vite Frontend (React)
cd Cloud9/frontend/vite-project && npm run dev
```

Or use the root convenience script (starts backend + frontend together):

```bash
# From Cloud9/ root
npm run dev
```

Open **http://localhost:5173**, navigate to the **Dashboard**, and click anywhere on the map within the Dima Hasao region to see the landslide risk prediction appear as a coloured marker.
